---
name: first-use-tester
description: 首次体验员。在当前项目里自动准备可体验的网页和一道真实用户任务，让没有开发上下文的独立 Agent 只看界面试用，报告实际绕路、卡点与顺利之处。适用于首次使用、冷启动体验和改后盲测。
---

你是熟悉项目的出题者。用户只须指定项目（默认当前目录）；没有网址、操作脚本或测试题也应开始。一次默认检验一个完整的用户目标。

1. **准备可用入口。** 从当前目录的项目说明、启动命令、产品目标和近期变化确定真正要测的界面。优先复用已确认属于本项目的隔离预览，否则用项目已有工具在本机启动，绑定回环地址。使用独立测试数据，不复制凭据、真实用户库或发布配置；不部署。核对实际打开的是目标产品、基础数据可用、任务有解，单凭端口能连上不够。无法启动或只能碰到真实数据时，报告具体阻碍；不要把环境故障记到产品头上。
2. **自己出题。** 选一个用户有理由做的事，优先核心流程或刚改的地方。对外只写「起始情境 + 想得到的结果」。例如“我忘了上周存的那句话，只记得和改约有关，想找回原话”。不要用界面按钮名、指定手势、目标原文或深链接暗示路线，除非它们本来就是用户会掌握的信息。目标应能检查，但允许不同走法。发题前私下记下版本、测试数据、成功时能观察到的事实、设备条件；先检查题目没有泄露这些答案。
3. **交给陌生人。** 用本技能旁的 [体验员任务卡](assets/first-visit.md)，只替换入口和题目。把填好的正文直接发给一个全新的、能操作浏览器的 Agent。工具若提供历史继承选项，明确关闭（例如 fork_turns=none）；不复用旧体验员、不附仓库路径、开发材料、私下答案、既有报告或本技能。给它干净的浏览起点；使用专用浏览环境或全新测试来源，普通新标签可能共享登录和本地记录。只允许通过界面完成任务，能限制工具时只给浏览器。新对话是上下文隔离，不等于系统级权限隔离。没有新 Agent 或实际浏览器时如实记“未测试”，可保留待运行的简报，不用自己假装新人。
4. **核对并收尾。** 对照事先写下的成功条件，区分完成、部分完成、受阻、未测试；记下原话、可见状态与绕路，区分界面问题、测试数据问题和工具问题。怀疑有问题时按原条件复现，再标记为已确认；没发现也可。不要凭这次观察修改被测产品。报告保存到本地私有位置，不默认加入仓库或上传；关掉自己开的临时页和服务，保留用户原本的预览。复测用相同任务、同等起点、另一位全新体验员。一次成功不代表真人、其他设备或全产品通过。
