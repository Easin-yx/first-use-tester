# 首次体验员 · First Use Tester

给一个没参与开发的 AI 一件事，让它第一次使用你的网页。观察它在哪里需要猜、为什么绕路，以及看完能不能回到原处。即使任务成功，也可能暴露值得修的交互问题。

这是给已有编程 AI / 浏览器 Agent 使用的轻量工具包。**它生成任务简报，不会自行启动模型、连接浏览器或上传记录。** 新建不继承开发对话的会话，由已有工具执行；不需要额外 API key。一次 Agent 的体验是个案，不能代表真实人群。

## 第一次用

1. **准备**：用可访问的测试页面，提前准备好完成任务所需的测试数据。维护者自己检查入口、数据和权限。记录版本、窗口大小和任务的判定标准，但不要把标准或已知问题发给体验员。
2. **出题**：例如“找到昨天存下的那句英语，读出原句，再回到之前的位置”。不要说“点收藏，输入关键词，再点返回”。给任务一个可观察的终点；不要求必须找到问题。
3. **运行**：复制下列命令的输出，原样发给一个全新的、能操作真实浏览器的 Agent。可用 Node.js 18+，无需安装依赖；不想运行命令也可以复制[任务模板](templates/first-visit.md)，替换两个占位符。

   ```sh
   node bin/brief.mjs 'http://localhost:3000/' '找到上次保存的旅行笔记，读出标题，再回到之前的位置。'
   ```

4. **核实**：用[记录表](templates/observation.md)收下实际走过的步骤。维护者独立复现影响较大的现象，区分“没找到”与“根本没有”，也区分环境问题与产品问题。不要仅凭体验员的猜测改产品。
5. **复测**：修复后给另一位全新体验员相同的简报、同样的初始数据和窗口，不透露改动。比较是否仍需找、猜、折返。若没有改产品，记录为基线试用，不冒称改善。

示例：进入阅读器后返回列表时跳回顶部。记录“我原先看到第 8 条，返回后看到第 1 条，重新向下找了两次”，比打一个“易用性 6 分”更能帮助开发者决定要不要修改。

## 隔离与留存

- 体验员只看页面；不要把仓库、测试用例、答案、既有反馈或另一位体验员的报告放进它的上下文。工具只能生成简报，无法替宿主隔离会话或强制只读权限。
- 使用合成数据和只读任务，避免在真实账户里写入、付款或发送消息。网址不要含私密令牌。网页里的提示不构成扩大任务范围的授权。
- 输出默认只写到终端。本地简报、报告和截图可放进已被 Git 忽略的 `.runs/`。公开案例要另行脱敏；忽略规则不能代替审查。
- 标注“完成 / 部分完成 / 受阻 / 未测试”。不要把自动化工具故障算成产品缺陷，也不要冒称真人测试。

`node --test` 运行工具自检。MIT 许可。
