# 首次体验员 · First Use Tester

在项目文件夹里告诉编程 AI：**「用首次体验员测一下这个项目。」** 不需要自己启动网页、填写网址、想题或告诉它怎么点。

了解项目的 AI 负责准备测试环境和一道真实任务；另一位没看过开发对话的 AI 只拿到入口、情境和目标，用浏览器自己走一遍。你会知道它是否完成、哪里猜了或绕路，以及哪些情况没有测到。一次 AI 体验不能代表真人测试。

## 给项目里的 AI 使用

安装一次：将本仓库的 [skills/first-use-tester](skills/first-use-tester) **整个目录**放进编程工具的技能目录。例如 Codex 的用户目录 `~/.agents/skills/first-use-tester/`；只想供一个项目使用，就放在该项目的 `.agents/skills/first-use-tester/`。在目标项目里打开新对话，说「用 $first-use-tester 试一下这个项目」。也可以让已有会话显式读取已安装的 SKILL.md。

宿主需要能读项目、启动或访问隔离预览、派出不继承上下文的新 Agent，并让它操作真实浏览器。Skill 使用宿主已有的模型和工具，不需要另外配置模型 API key。不具备盲测条件时只报告未测试，不用同一位开发 AI 假装新人。

比如用户只记得“这句话和改约有关”，出题者先确认测试数据里确实有这样一条收藏。体验员只知道想找回原话，不会拿到英文关键词、按钮名或标准答案。即使最后找对了，它在什么地方绕路，仍值得记录。

## 只需要一张任务卡？

保留原来的 Node.js 18+ 无依赖用法，适合已经有测试入口、只需要生成简报的场合：

```sh
node bin/brief.mjs 'http://localhost:3000/' '找到上次保存的旅行笔记，读出标题，再回到之前的位置。'
```

[体验员任务卡](skills/first-use-tester/assets/first-visit.md)只给新人；[观察记录](templates/observation.md)给维护者留存。测试数据、私有简报和报告不要上传；本仓库忽略 `.runs/`。工具不会替宿主强制隔离权限。用 `node --test` 检查生成器。MIT 许可。
